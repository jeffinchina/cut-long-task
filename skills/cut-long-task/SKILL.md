# 长任务分段

用户只需选择一种恢复方式，其他续做细节由本技能负责。技能自包含，不依赖安装 `task-finish-clock`。

## 最简调用

```text
$cut-long-task 今晚21:00、明天09:00
$cut-long-task 额度刷新后7分钟
$cut-long-task 额度刷新后7分钟，15%
```

- **固定时点**：给一个或多个具体时间，只在这些时间检查，不自动增加时间点。
- **刷新后延迟**：写“额度刷新后N分钟”，即授权为同一任务按真实五小时刷新时间逐轮续接，默认直到完成、用户取消或需要人工处理的真实阻塞；无需再写“每次”“读取 resetsAt”“唯一下一节点”或截止日。可选“直到11月2日全天结束”来限制期限，写“仅本次”才只安排一次恢复。
- **保留比例**：新的用户调用未给比例时统一使用 `T=0.2`；`20%` 与 `0.2` 等价，不沿用历史的15%等旧参数。自动恢复轮必须沿用当前计划保存的 T，不把默认值重新覆盖到用户指定值。
- 明确的旧任务截止限制和授权撤销仍有效；续用同任务时，省略截止日不自动取消原来的期限。新计划未设截止日则按任务终止条件停止。
- 默认立即推进主任务并先建立恢复计划；只有用户说“先暂停”“到点再开始”才延迟启动。创建/修改本技能不算调用运行计划，不执行说明中的示例任务。

## 绑定任务与解析参数

绑定调用附带的主任务，或本对话最近一个明确的实质性任务；保存稳定标识、目标与验收要求、工作目录、产物和原授权。沿用同任务的检查点、正确成果及现有审批策略，用户不必重复这些信息。任务不唯一时才澄清，不把“创建恢复节点”误当工程任务。

只解析独立的调度参数和保留比例，不把日期、钟点、主任务里的百分比误当阈值。小数范围 `[0,1]`，百分比范围 `[0%,100%]`；裸值20、越界或冲突值先澄清。`0` 无预留缓冲，`1` 立即暂停。N 为非负整数分钟；只说“额度刷新后”而未给 N 时默认7分钟。旧调用中的5–10分钟区间兼容选7分钟并说明，其他模糊区间才澄清。

时间使用用户指定时区，否则使用环境时区；无时区信息才询问。固定时间去重排序，无日期钟点取下一次出现；明确过期或歧义时间需澄清。截止日按同一时区；“全天结束”表示当天23:59:59。两种模式不混建；用户同时要求两种且无法确定替换关系时才澄清。缺少模式/时间或参数无效时先保存必要进度，不启动新的高消耗阶段或创建不完整计划。

## 额度门槛

执行/恢复前使用真实额度工具（如 `get_usage_limits`）；除读取本技能、当前指示和紧凑计划摘要外，先读实时额度，再展开耗时工程文档。明显已完成或已取消的任务直接按终止规则处理。

- 优先 `rateLimitsByLimitId`，缺失时才用 `rateLimits`；只选当前任务/模型适用的桶，并按 `windowDurationMins=300` 识别五小时窗口，不按 primary/secondary 的名字猜测。多个适用窗口取最小剩余比例；不要混入其他模型或 Code Review 桶。
- `R=clamp(100-usedPercent,0,100)/100`。`usedPercent` 是**已用**比例，**R > T 才推进，R <= T 保存暂停**。周额度耗尽、服务端禁用等另记为硬限制，不把保留比例套到周额度上。
- 历史 `usedPercent/resetsAt` 和 `paused_quota` 只作审计，不能决定本次继续暂停；每次重新读。工具失败、数据缺失/过期、桶不明或实际无五小时窗口时有界重读一次，仍不可验证就保存并准确报告，不声称“额度耗尽”或降级成无限制执行。
- 可选用 [scripts/quota_gate.py](scripts/quota_gate.py) 对**本次真实工具返回值**作纯计算。它不读历史状态、不调用网络、不创建计划；其 `next_check_utc` 只供刷新模式计算使用，固定模式不得因此增建节点。
- 额度跨同账号任务/设备共享；按检查点尽力预留，无法精确卡住阈值。不能暂停无关任务、修改审批/模型/套餐、购买额度、消耗重置券或绕过权限。

## 内置执行流程

创建、更新或执行任何恢复计划前，读取 [references/resume-plan.md](references/resume-plan.md)，按其中对应模式建立当前对话内的一次性 heartbeat。**固定模式维护用户时间表；刷新模式至多维护一个未来节点，每轮用实时 resetsAt 重算。** 只修改本对话同一任务的精确匹配计划；实际操作后独立核验，失败不算安排成功。

1. 复用或建立 [references/checkpoint.md](references/checkpoint.md) 所述的紧凑检查点，先按对应模式核验计划，再进入耗时工作。有效的最后一个固定节点可直接承接本轮，不要求再造未来节点；刷新链按引用规则先接好后继。配置完成只作中间进度，默认模式不得因此结束主任务。
2. 按可保存、可重入的小单元执行。每单元开始前、完成后，以及高消耗调用/派生代理前检查额度；长阶段在可交还控制处约每五分钟再查，接近阈值时拆更小。无法在工具内部或持续生成中硬中断，故持续保存成果。
3. 触及保留线、读数不可验证、硬限制或截止日到达时停止领取新工作，只做避免数据损坏所需的最小收尾。派生代理继承分段约束，并及时保存/暂停本任务的模型执行；安全且不消耗模型额度的本地进程可留存查询标识。不影响其他对话或项目。
4. 保存代码/文档、已有测试证据、验收状态、未完成项及下一步恢复说明。核验未来节点：固定模式选尚未消费且仍在未来的一项；刷新模式按实时读数维护唯一下一项。随后结束当前轮，不在本轮睡眠等待数小时或偷偷继续主任务。
5. 恢复先核对最新用户限制和本节点身份，再用新额度决定；不把本轮自身的 running 状态当另一执行者，也不只凭陈旧 running 文本跳过。重试外部动作前核对真实结果，保留用户修改，不重复发信/提交/发布。

任务真正达到验收要求才标记完成；本轮新增完成成果可简短交付，后续已完成检查静默。最后一个固定节点仍可推进至完成或实际需要暂停，届时未完成且无未来项才记 `needs_time`、请补时间；刷新链到期记 `expired`；不可验证、权限/审批失败或需用户决策记真实阻塞，不把它们混称额度不足。取消、完成、授权撤销或真实人工阻塞后停止续建，并按调度规则停用本任务自己的待执行节点。相同暂停/阻塞状态且仍有有效后续节点时静默，不发例行进度。

首次确认只需简短给出任务、保留比例、固定时间表或“刷新后N分钟”的当前下一节点、可选截止日、时区和实际创建结果；说明本地恢复需电脑在线且客户端运行。用户无需抄写内部持久提示词、RRULE 或技术约束。
