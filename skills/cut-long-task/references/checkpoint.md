# 可恢复检查点

在首次执行前、每个工作单元结束后和暂停时更新本任务检查点；先读取现有内容及实际产物，保留用户修改。恢复时此文件提供线索，实际状态与用户最新指示优先。不要用它的 `running` 字样充当不可过期的执行锁。

按任务需要填写以下信息，省略不适用项，不记录凭据：

```text
任务标识 / 当前 thread：
技能：cut-long-task；本机 SKILL.md 绝对路径：
状态：running | paused_quota | paused_unverified | blocked | needs_time | completed | cancelled
最后更新时间 / 时区：
目标和验收条件 / 原授权范围 / 用户后续修改：
工作目录 / 产物绝对路径：
适用 AGENTS.md 和其他技能：

保留比例 T：0.2（20%，或用户指定值）
最近真实额度观测时间：
适用 limitId / windowDurationMins / usedPercent / 计算后的 R / resetsAt：
不可读或硬限制的具体原因（如适用）：

已完成且已验证的工作：
正确的半成品 / 已改文件 / 已做外部操作及核验状态：
下一单元 / 待办 / 必须执行的验证：
本任务派生代理的标识、状态、已存成果和未完成项：
仍运行的进程/会话及安全查询/接续方式：

每个用户指定恢复点：绝对时间和时区、automation ID、配置验证结果、pending/consumed/failed/cancelled
下一个仍有效的已确认恢复点（或无）：
上次有意义通知及原因（避免重复提醒）：
```

恢复处理顺序：

1. 读最新用户指示，核验是否取消、已完成或在本次恢复轮之外已有执行者；本次恢复自身的 running 状态不算重复执行。校对真实产物和外部操作。
2. 本次机会只运行一次；将已消费或执行期间已过去的时间点与未来时间点区分，必要时读取本任务自动化实际状态。
3. 读取新的适用五小时额度；不可验证或 `R <= T` 时不开始实质工作。
4. 可推进时先更新状态，完成小单元后再保存成果、额度和下一步；触发暂停后重新选取未来有效时间点。
5. 无未来时间点时记录 `needs_time` 并仅提醒一次；真正完成时记录 `completed`，后续检查静默。
