# 恢复计划：两种输入、一套内部工作流

仅当用户调用本技能来运行主任务时创建/修改自动化；技能维护请求不触发示例任务。本技能调用已包含“复用同任务检查点、更新本技能该任务旧计划”的请求，不要再次要求用户写出这些固定细节。

## 通用规则

- 使用正式自动化工具（如 `automation_update`），当前 thread、同一工作目录、一次性 heartbeat，每项仅发生一次（如 COUNT=1）。不要改为 cron、新对话或固定频率轮询。
- 持久化 `task_id / thread_id / plan_version / mode / T / delay_minutes / deadline / node_id / node_status`。参数/模式变化递增版本；新节点提示词仅含当前参数，不复制旧阈值、整段对话或历史大测试。
- 先定位并读取当前线程同一稳定任务的节点；匹配键包括技能、线程、任务、版本和该次绝对时间/刷新窗口。完全匹配则复用；参数变更优先更新精确 ID，不能新旧并存。重复调用或不明结果先读取消歧，再决定是否重试。
- 替换本技能同任务旧计划时，先清点匹配节点并阻止陈旧版本继续工程；能更新则更新原 ID，需重建则核验新节点后立即精确停用被替代节点。最终不能留下两个有效的未来刷新节点。无法安全替换或匹配不唯一时报告阻塞，不批量清理。与其他技能的计划存在冲突时，仅在有相应替换授权时修改它们。
- 变更后独立查看，核对 ACTIVE、heartbeat、当前 thread、单次、绝对时间/时区、任务、版本、阈值。配置 ACTIVE 或 COUNT=1 本身不证明“尚未消费”；用持久消费记录及实际运行信息判定。必要时用官方工具停用/删除精确旧 ID，不直接写内部数据库。
- 每次运行先识别本节点和版本。已消费/失效/被替代的重复触发不做工程、不另建链；除安全清理该精确 ID 外直接退出。首次有效触发只消费一次，把后继关联保存到检查点，避免重试多建。
- 调度只由当前 thread 的主执行轮维护，派生代理不创建/修改节点。有效恢复节点触发后，由该节点对应的主执行轮接本次后继，写入 `schedule_owner`（节点ID/执行轮标识及状态）；尚在工作的原工程轮只复用已登记后继，不同时创建。读取真实运行状态才可接管失效维护者，身份不明时保存并报告，不声称已取得互斥。
- 每次变更后再次列出本任务本版本的未消费节点核验唯一性；刷新模式若发现重复，保留已核验且参数/窗口正确的唯一后继，精确停用已确认多余项。无法安全确认、清理或判断谁维护时停止调度并报告，不宣称具备平台未提供的原子锁或并发硬保证。
- 核验完成、取消或撤销时停止链，精确停用本技能该任务的待执行节点；不得触及本轮用户另设的独立兜底、其他对话、其他任务或其他项目计划。不要把技能升级当成迁移所有已有定时任务的授权。

## 固定时点 fixed

只建立用户给出的未来时间点，去重排序并逐项独立核验；错过/消费的项不补跑、不滚到次日、不根据 resetsAt 增建。到点 R > T 才推进，R <= T 就保持暂停并等后续项。最后一个有效节点触发且额度允许时，先使用本次机会推进至完成或下一实际暂停点，不因“消费后已无未来项”当场拒绝续做；实际需要暂停且仍未完成时，无未消费的未来项才保存 `needs_time` 并提醒一次。首次启用时所有节点创建失败仍按失败暂停，不属于此例外。

仍有本次恢复之外的同任务执行轮时，不重复推进工程；消费本次机会后退出，剩余固定项不改期。没有剩余项则如实记录，不伪称未来还能恢复。

## 刷新后延迟 refresh

“额度刷新后N分钟”本身就授权动态逐轮续接，不要求另写“每次”或截止日。新计划默认至完成/取消/真实人工阻塞；可选截止日限制节点与工程执行，旧任务仍有效的截止限制不能因省略而被撤销。“仅本次”设 `single_refresh`，只建一个恢复点，消费后不续建；后续仍需暂停但无节点时提醒补充安排。

### 只用真实刷新时间

1. 每次开始/恢复/暂停都调用真实额度工具。对适用五小时窗口，触线窗口有多个时取**触线窗口** resetsAt 的最大值；尚未触线时取适用窗口最早的有效 resetsAt 来接好下一窗口的兜底，暂停时再重新计算。
2. 下一目标 `next_at = 本次观测的 resetsAt + N*60`；不是 now+N，不是 now+5小时+N，也不是上一节点+5小时。resetsAt 是 Unix 秒，先按绝对时刻计算再转用户时区显示。不能用历史检查点预估多个未来窗口。
3. 目标必须晚于创建时刻，且不晚于可选 deadline。resetsAt 已过、目标已过或数据不可验证时短间隔重读一次；仍无有效未来目标就保存 `unverified` 并报告，不挪到明天、不编造重试时间。若目标超过 deadline，记 `deadline_no_next`，不追加截止日检查或假称仍有恢复；当前若额度允许且尚未到截止日可继续，但须说明已无期限内的后继节点。
4. 实际触发超过截止日时不启动工程；执行中跨过截止日时在下一个可交还控制的检查点最小收尾。无法承诺在不可中断操作中精确卡秒。

### 维护唯一下一节点

- 开始长阶段前，从实时读数接好**一个**已核验未来节点；与现有精确匹配项复用/更新。刷新模式不预建未来多个窗口，不建周期额度轮询。
- 有效节点触发后，先读当前紧凑状态和新额度。完成/取消则清理停止；需要人工处理的真实阻塞则保存并停止续建。
- 未完成且属于持续刷新模式时，消费本次后，在继续耗时工程**之前**核验/接上一个新的未来节点；暂停时重读额度，更新这一未来节点，不额外叠加。R > T 即续做；R <= T 即保存暂停，后继仍由本次真实 resetsAt 计算。
- **busy 也必须接链**：若本轮之外有同任务执行者，先避免重复工程，由本次有效恢复节点的主执行轮按通用维护权规则核验/接好唯一后继再退出；原执行轮随后发现该节点应复用。不把当前恢复轮自身的 running 当忙碌；恢复轮退出也不证明原工程轮已暂停，必须以其真实检查点/代理状态为证。连续相同窗口但目标已消费且不能得到新未来时间时有界重读，仍不成立按 unverified 停止，不自旋复建过去节点。
- 自动化操作结果不明先正式读取；仅有界重试，不盲目新建。创建/验证失败时准确报告 `schedule_failure`、具体错误和实际保留的节点；没有已核验后继就暂停工程，不能静默丢链并继续长跑。尚有安全可用旧节点时保留并明确实际安排。截止限制导致无后继按上一节处理。
- 真实硬限制与保留线分开：五小时保留线可等下一刷新；周额度耗尽、权限/审批容量失败、需要用户决策不靠再等五小时就宣称可解决，记录真实原因，停止无意义续建并报告一次。

## 持久提示词由技能生成

用户无需输入下列细节。每项提示词包含足以独立恢复的紧凑快照：任务/线程/版本/节点身份，原目标与验收条件、范围与权限，工作目录/产物、检查点绝对路径、本技能与适用 AGENTS.md/其他技能路径；无文件时嵌入最小状态。按模式保存 fixed 时间表，或 refresh 延迟、当前真实窗口标识、当前唯一下一节点、是否仅本次及可选 deadline。不要把默认20%覆盖到本计划用户指定的15%。

核心语义：

> 读取 cut-long-task 及 resume-plan.md、最新用户指示和紧凑检查点；取消/已完成则按终止规则清理本任务节点并静默。确认本节点版本有效且尚未消费，排除自身 running 后识别其他执行者。推进工程前重新读取适用的五小时额度，用本计划 T 比较，历史 paused 状态不决定本轮行动。消费本次机会一次，按 mode 维护未来计划：fixed 只用给定表，refresh 用本次真实 resetsAt+N分钟维护唯一后继，busy 分支也不丢链；single_refresh 不续建。可推进才从已验证成果接续，触线就保存暂停；重复外部动作前读真实结果。不得扩权、改变现有审批、模型、套餐或购买/重置额度。按截止限制、失败处理和通知规则结束本轮。

节点创建后只报告已独立核验的真实结果。普通重复暂停/重复检查静默；新增完成、实际失败、首次有意义暂停或确需用户处理时简短通知。记录 decision/reason，区分 resume、reserve_threshold、unverified、busy、completed、cancelled、hard_limit、approval_failure、schedule_failure、schedule_exhausted、expired 和 deadline_no_next。
